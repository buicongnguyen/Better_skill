Thiết lập môi trường

Từ thư mục trên máy đến game mà người khác có thể mở.

Lộ trình nhập môn dùng tác nhân lập trình cục bộ, Git, GitHub và game tĩnh TypeScript/Vite/Three.js. Thiết lập trước mười một prompt trong cẩm nang. Nếu đã có công cụ hoặc tài khoản, kiểm tra và dùng lại. Chương mô tả hành động cho dự án game; đọc sách không tự cài phần mềm hay cấp quyền. Đã kiểm tra hướng dẫn cài và truy cập tài khoản ngày 14/9/2026. {{cite:56}} {{cite:58}}

1 · Cài công cụ phát triển

  1. Cài Git cho Windows; cùng trang có hướng dẫn macOS và Linux. Git lưu lịch sử cục bộ. {{cite:58}}
  2. Cài Node.js LTS còn được hỗ trợ cùng npm, tương thích phiên bản Vite đã chọn. Đây là công cụ build game, không phải điều kiện để cài tác nhân desktop. {{cite:59}}
  3. Cài GitHub CLI để thao tác tài khoản/repo. Đây là chương trình khác Git. Mở lại terminal và tác nhân sau khi cài để nhận đường dẫn mới. {{cite:61}}

Trong PowerShell trên Windows hoặc terminal trên macOS/Linux, kiểm tra công cụ. Mỗi lệnh phải in phiên bản. Nếu không tìm thấy lệnh, cần xử lý cài đặt hoặc PATH.

git --version
gh --version
node --version
npm --version

2 · Tạo thư mục và mở bằng Codex

  1. Tạo thư mục độc lập như Documents/signal-garden trong trình quản lý tệp. Tránh đặt game mới trong repo của cuốn sách.
  2. Theo hướng dẫn desktop chính thức và hướng dẫn tải Windows. Tài liệu hiện gọi ứng dụng là ChatGPT desktop; chọn Codex để phát triển phần mềm. Bản Codex đã cài có thể dùng điều khiển dự án/thư mục tương ứng.
  3. Đăng nhập tài khoản ChatGPT, mở thư mục game thành dự án và bắt đầu tác vụ lập trình cục bộ ở đó. Kiểm tra đường dẫn tuyệt đối trước khi sửa. Chọn GPT-6 Astra nếu có trong bộ chọn model; quyền tài khoản và tùy chọn model có thể khác nhau.

Môi trường cục bộ được chọn phải có công cụ ở bước 1. Phiên WSL hoặc máy từ xa có môi trường riêng, có thể cần công cụ và xác thực riêng. Giữ giới hạn quyền của ứng dụng; cấp quyền cụ thể khi hành động cần thiết yêu cầu. {{cite:56}}

3 · Tùy chọn: dùng Claude Code trong ứng dụng desktop

Theo hướng dẫn desktop Claude, đăng nhập, chọn Code → Local → Select folder rồi chọn thư mục game. Tab Code cần gói đủ điều kiện; tài khoản chat miễn phí không đủ cho lộ trình này. Cần Git cho cách ly worktree và quy trình quản lý phiên bản của sách. Bản ứng dụng Windows cũ còn yêu cầu Git trước mọi phiên cục bộ. Desktop tích hợp Claude Code; chỉ cần cài CLI riêng nếu muốn chạy claude từ terminal. {{cite:57}}

Dùng một tác nhân tại một thời điểm trên cùng checkout. Để so tác nhân, dùng nhánh/worktree riêng cùng mốc và tác vụ đánh giá. Prompt có thể chia sẻ tài liệu dự án, nhưng chọn model và tìm tệp chỉ dẫn thuộc từng ứng dụng; không mặc định tác nhân nào cũng tự đọc cấu hình của tác nhân khác. Xem cách chọn công cụ và skill.

4 · Tạo quyền truy cập GitHub bằng HTTPS

  1. Tạo tài khoản GitHub, xác minh email và thiết lập bảo vệ tài khoản. Bỏ qua nếu đã có tài khoản. {{cite:60}}
  2. Chạy lệnh đăng nhập dưới trong terminal cục bộ. Tự hoàn thành đăng nhập trình duyệt. Nếu được hỏi xác thực Git bằng thông tin GitHub, chọn Yes. {{cite:61}}
gh auth login --hostname github.com --git-protocol https --web
gh auth status

Chạy kiểm tra trạng thái trong môi trường tác nhân nữa. Đăng nhập Codex độc lập với GitHub. Xác thực GitHub CLI cũng có thể cấu hình thông tin Git HTTPS nên SSH là tùy chọn. Không đưa mật khẩu, token hay khóa riêng vào chat hoặc commit. GitHub CLI thường dùng kho thông tin đăng nhập của hệ điều hành; tài liệu nêu sẽ dùng tệp văn bản thuần nếu không có kho hoạt động được. {{cite:61}}

5 · Tùy chọn: chọn SSH

Nếu thích SSH, theo hướng dẫn khóa và ssh-agent đúng nền tảng. Kiểm tra khóa hiện có trước; không vô tình ghi đè. Có thể tạo khóa mới bằng lệnh dưới sau khi thay nhãn email. Thêm mật khẩu bảo vệ và làm theo hướng dẫn hệ điều hành. {{cite:62}}

ssh-keygen -t ed25519 -C "your_email@example.com"
# Sau khi thêm khóa công khai vào GitHub:
ssh -T git@github.com

Chỉ thêm khóa .pub tại GitHub Settings → SSH and GPG keys. Trước khi chấp nhận máy chủ mới, so dấu vân tay với danh sách chính thức được GitHub liên kết. Bài kiểm tra phải hiện đúng tên tài khoản; thành công vẫn có thể trả mã 1 vì GitHub không cung cấp shell tương tác. Dùng remote SSH như git@github.com:YOUR_ACCOUNT/signal-garden.git. GitHub CLI vẫn cần đăng nhập riêng để thao tác API như tạo repo. {{cite:62}} {{cite:61}}

6 · Kiểm tra dự án và đặt danh tính commit

Dán prompt chỉ đọc này vào chat của dự án đã chọn. Nó kiểm tra mức sẵn sàng trước khi cẩm nang bắt đầu tạo tệp.

{{prompt:setup-preflight.md}}

Sau khi Git được khởi tạo cho dự án tại bước 4 cẩm nang, đặt tên/email tác giả còn thiếu bằng lệnh cục bộ dưới, thay cả hai giá trị, rồi tiếp tục commit. Cài đặt email GitHub hiển thị địa chỉ no-reply nếu bạn muốn giữ riêng tư email. user.name và user.email ghi danh tính trên commit, không đăng nhập GitHub. {{cite:58}}

git config --local user.name "Your Name"
git config --local user.email "YOUR_VERIFIED_OR_GITHUB_NOREPLY_EMAIL"

Lưu tệp, commit, push và triển khai là bốn kết quả khác nhau. Muốn hiểu mã hiện có, yêu cầu tác nhân lần đầu vào → trạng thái → hiển thị, dẫn tệp và lịch sử Git; xem công thức sửa lỗi. Commit không chứng minh game hoạt động.

7 · Xuất bản bằng GitHub Pages

Hoàn thành và thử game cục bộ trước. Lộ trình GitHub Free nhập môn này dùng repo công khai và chỉ xuất bản nội dung muốn công khai. GitHub Pages phục vụ tệp tĩnh; không chạy máy chủ dev Vite hay backend multiplayer. {{cite:46}}

  1. Dùng prompt phát hành Pages với đúng tài khoản và repo.
  2. Với URL dự án https://YOUR_ACCOUNT.github.io/signal-garden/, đặt Vite base là /signal-garden/. Build và xem thử đầu ra cục bộ.
  3. Trong repo GitHub, chọn Settings → Pages → Source: GitHub Actions. Tác nhân chuẩn bị workflow build/triển khai, commit và push tệp đúng phạm vi. Xem hướng dẫn Pages đầy đủ.
  4. Chờ workflow của đúng commit, rồi xác minh URL công khai, asset, thắng, thua và chơi lại. Push thành công chưa phải game đã triển khai.

Tài liệu triển khai Vite mô tả base path, đầu ra build và lộ trình Actions. dist là đầu ra mặc định; kiểm tra cấu hình dự án thật. {{cite:12}} {{cite:13}}

8 · Hoặc xuất bản bằng Vercel Hobby

Vercel Hobby là gói miễn phí cho sử dụng cá nhân, phi thương mại, có hạn mức. Đây không phải gói miễn phí chung cho doanh nghiệp hay game thương mại. Kiểm tra điều kiện hiện tại trước khi chọn. {{cite:64}}

  1. Dùng prompt phát hành Vercel sau khi điền đích GitHub và Vercel.
  2. Với game Vite tĩnh ở gốc tên miền, dùng base: '/', lệnh build của dự án (thường npm run build) và thư mục đầu ra (thường dist). Nếu dùng cả hai host, cấu hình base riêng cho mỗi lần triển khai.
  3. Trong New Project của Vercel, nối GitHub, cấp quyền repo đã chọn và nhập nó. Rà tài khoản/phạm vi, thư mục gốc, preset Vite và cài đặt build rồi triển khai. Tích hợp này cần quyền repo riêng; SSH không tự cấp quyền đó.
  4. Hoặc cài Vercel CLI bằng npm install -g vercel và chạy vercel login. Trong thư mục game, rà các câu hỏi dự án/phạm vi; dùng vercel --prod khi sẵn sàng công khai production. Lộ trình dashboard không bắt buộc skill hay máy chủ MCP.
  5. Kiểm tra URL production vercel.app được cấp khi đã đăng xuất, revision, asset và gameplay. Push Git đã kết nối có thể kích hoạt triển khai sau; phân biệt URL preview với production.

Hướng dẫn bắt đầu chính thức có cả CLI và dashboard. Tài liệu Git và Vite của Vercel giải thích tích hợp và hành vi framework. Repo mã nguồn riêng tư vẫn không che được bí mật nhúng trong JavaScript phía trình duyệt. {{cite:63}} {{cite:12}}
