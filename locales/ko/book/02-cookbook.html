복사해서 쓰는 프롬프트

빠른 요약의 각 단계에 대응하는 예제 프롬프트입니다.

환경 설정부터 시작하세요. 이 독창적 예제는 Signal Garden 규칙을 따릅니다.

게임 폴더에 연결된 채팅에 한 번에 하나씩 붙여 넣고 결과를 확인한 다음 진행하세요. 예제를 바꿀 때는 합의한 자신의 요구 사항을 유지하세요.

제안된 절차이며 벤치마크나 한 프롬프트로 완성된 게임을 얻는다는 보장은 아닙니다.

저장소·실행 도구가 없는 챗봇은 명세나 프롬프트 작성을 돕지만 로컬 코드 검사, 테스트, 공개는 할 수 없습니다. 해당 단계에는 폴더와 필요한 도구에 접근하는 코딩 에이전트를 사용하세요.

Claude Code에서는 제공되는 Claude 모델을 사용합니다. 프롬프트에 “Astra”라고 적어도 모델이 바뀌지 않습니다.

프로젝트 파일을 지속적인 기준으로 유지하세요. {{cite:56}} {{cite:57}}

처음의 짧은 블록만 바꾸고 상세 지침은 유지하기

  1. 전체 프롬프트를 아직 보내지 않은 채팅 초안에 복사하세요. 그다음 시작 블록을 수정하고 제목과 줄바꿈을 유지하세요.
  2. 시작 매개변수를 수정하세요. 에이전트 하나와 선택지가 있는 경우 엔진 또는 영상 도구 하나를 고르세요. 프로젝트에 맞는 나머지 기본값은 유지합니다.
  3. 실제 환경과 맞추세요. 앱에서 모델을 선택하고 올바른 폴더를 여세요. 모델이나 도구 이름을 입력해도 자동으로 활성화되지 않습니다.
  4. 하나의 기준 규칙을 유지하세요. 명세 작성 때 설계 변경을 RULE_CHANGES에 적고 이후 단계는 합의한 문서를 사용하세요. 엔진을 바꾸려면 기존 작업과 먼저 조정해야 합니다.
  5. 확인한 다음 계속하세요. 결과를 완료 조건과 비교합니다. 출시 프롬프트의 PUBLISH: YES는 명시한 대상 공개를 승인하며 NO는 로컬 준비만 뜻합니다.

RTS 계획 예제에서 배운 점

제공된 RTS 계획은 범위, 작업 묶음, 조정값, 완료 검사를 분리합니다. 이 책은 매개변수 → 목표 → 작업과 제약 → 완료 조건 구조를 적용합니다.

전체 게임 명세는 프로젝트 문서에 둡니다. 후속 프롬프트는 다음 유용한 결과를 요청하고 해당 문서를 참조하세요. 필수 게임 규칙은 명확히 하되 일상적인 구현 세부 사항은 에이전트가 선택하게 합니다. 항목이 많아진 것만으로 더 좋은 게임이 입증되지는 않습니다. {{cite:17}}
