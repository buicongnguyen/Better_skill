Make a video with an agent

A video workflow can contain skills, MCP, and hooks. The flow itself is a separate idea.

The exact page you saw has not been identified, so we cannot name its software with certainty. A canvas of linked model nodes is often a tool such as ComfyUI. A canvas of HTTP requests, waiting steps, and conditions may be an automation tool such as n8n. An agent calling a media service may use MCP. Below are verified examples and a practical way to choose among them.

A current change worth noticing

Remotion’s documentation, updated 12 September 2026, deprecates its older documentation MCP and recommends agent skills instead. This is evidence of one redundant documentation integration, not evidence that MCP or skills are universally obsolete. Its job was to provide docs; an MCP server that actually submits video jobs has a different role. {{cite:27}}

Make a shot manifest: one record per stable shot ID, with purpose, duration, source type, reference files, prompt when needed, output path, and review status. Record model/version, settings, task ID, attempt number, and actual cost where the service exposes them. This is your project record, not a universal provider request schema. Keep credentials in the tool’s credential store, outside the manifest and public repository.

For a generated establishing shot, try a focused visual prompt: “A small rooftop garden at dusk, a single amber beacon at the center, low planters, muted green concrete, a slow elevated camera push toward the beacon, stable geometry and lighting.” Supply duration, ratio, and a reference image through the service’s supported controls. Add titles during composition. Compare one relevant change at a time instead of replacing the entire prompt whenever a clip disappoints.

4 · Use ComfyUI when you want a visible generation graph

Start from the application’s Workflow Templates browser and inspect the selected template’s model and input requirements. Templates provide a concrete starting graph, while the reviewed LTX-2.5 guide covers text-to-video, image-to-video, and first/last-frame workflows with supported audio. Model access and a compatible installation matter; a new model name alone does not make a graph runnable. {{cite:29}} {{cite:28}}

5 · Use an API when you want explicit job handling

Runway’s multi-shot recipe, version 2026-06, supports automatic story decomposition or a custom shot list. Its shown schema generates the shots; it does not insert our existing gameplay captures. Use it for a separately labeled all-generated concept trailer. For the mixed-source storyboard above, compose SG-02 and SG-03 from real capture in Remotion. A three-shot, ten-second concept variant fits the documented timing options, but has not been run here. {{cite:32}}

There is also an important MCP distinction in Runway’s own documentation: https://dev.runwayml.com/mcp serves developer tasks and documentation, while https://mcp.runwayml.com is identified as the separate media-generation integration. Do not configure the developer endpoint and assume it exposes a video-generation tool. Inspect the connected server’s actual capabilities. {{cite:30}}

{{diagram:video-job}}

Runway’s SDK documentation describes asynchronous tasks and polling. Follow its current polling interval and backoff guidance; its manual polling example says at least five seconds with jitter. A local waiting timeout does not prove the remote job failed or was canceled. Keep the task ID and check it before considering a new paid attempt. {{cite:31}}

PENDING, RUNNING, and THROTTLED are nonterminal states. A throttled task has been accepted but is waiting for capacity; it is distinct from an HTTP 429 response. For retryable status-request errors, use bounded backoff and jitter. Stop on a fatal error, unknown state, or deadline and preserve the task record. If the initial submission has an uncertain result and no ID, reconcile it through provider records before submitting again. These recovery choices are our proposed orchestration policy. {{cite:47}} {{cite:48}}

Save accepted output to storage you control. Runway’s output URLs are temporary, typically expiring within 24–48 hours of access. A task record should point to the saved file as well as the original task, so a later edit does not depend on an expired delivery URL. {{cite:33}}

6 · Build the repeating flow in n8n

Once one request succeeds, reproduce its working method, URL, authentication, headers, and body in an HTTP Request node. That node makes API calls; the video provider performs the generation. Use n8n credentials for authentication. {{cite:34}}

  1. Manual trigger: load one approved shot and its allowed attempt budget.
  2. Submit: send one generation request per attempt; persist the returned task ID and shot ID. An uncertain submission goes to reconciliation.
  3. Wait: pause for the provider’s required interval while within the deadline.
  4. Check: GET that same task; route pending, running, or throttled back to Wait. Handle retryable HTTP errors with bounded backoff.
  5. Resolve: save successful output; record failure, cancellation, unknown status, or local timeout for review. A local timeout does not cancel the remote task.
  6. Assemble: use reviewed clips in the timeline, then watch the full export before publication.

The job diagram above is the logic to reproduce with HTTP Request, Wait, and conditional branches. The Wait node can resume after time or through a webhook. Use a callback only when the selected provider documents one, and configure its authentication. A webhook is an incoming HTTP event; it is distinct from an agent’s lifecycle hook. {{cite:35}}

Keep generation submission outside the status-polling loop. If a request’s result is uncertain, reconcile the existing task before retrying. Workflow recovery should not silently multiply paid jobs. Automating a reviewed small pipeline is easier to diagnose than beginning with a large imported template whose endpoints and models may have changed.

7 · Add a hook only for a repeated event action

{{diagram:hook-flow}}

A proposed hook could run an existing local validator after the agent edits the shot manifest. That validator checks duration totals, required shot fields, and local asset references. Filter irrelevant edits out. First run the validator directly and confirm that its feedback is useful; then wire it to your host’s supported event configuration.

Current Codex hooks include PostToolUse, which runs after a tool finishes. It cannot undo that completed action. Configuration and trust requirements belong to the host; consult the current hook guide rather than copying another application’s configuration. Hooks can automate narrow checks, while the main agent or workflow coordinates the project. {{cite:24}}

Review the result and improve the right layer

If a shot communicates the wrong idea, fix its intent. If motion is unstable, change the relevant generation input or choose a different source clip. If text is misspelled, compose the text in the edit. If files expire, fix storage. If duplicate jobs appear, fix orchestration. A longer skill file does not address all of these causes.

Keep the storyboard, non-secret settings, decision notes, composition code, and appropriate asset references in GitHub. GitHub Pages can serve static public media within its hosting limits; it does not provide the worker for long generation jobs or secret-bearing API calls. Review the complete export and confirm the publication destination. {{cite:46}}

Your first useful experiment

Prepare the ten-second storyboard, capture one genuine gameplay shot, and build a composition preview. Generate one concept clip only if it adds something the capture cannot provide and its cost is authorized. Record what improved the trailer before adding another model, skill, MCP server, or automation step.
