Set up your environment

From a folder on your computer to a game that other people can open.

This beginner route uses a local coding agent, Git, GitHub and a static TypeScript/Vite/Three.js game. Setup comes before the eleven cookbook prompts.

If tools or accounts already exist, check and reuse them. This chapter describes actions for your game project; reading it does not install software or grant access.

Installation and account availability were checked on 14 September 2026. {{cite:56}} {{cite:58}}

1 · Install the development tools

  1. Install Git for Windows; the same site links macOS and Linux instructions. Git stores local history. {{cite:58}}
  2. Install a supported Node.js LTS release with npm compatible with the chosen Vite version. This is for building the game, not a requirement to install the desktop agent. {{cite:59}}
  3. Install GitHub CLI for account/repository operations. It is a different program from Git. Reopen the terminal and agent after installation so they see updated paths. {{cite:61}}

In PowerShell on Windows, or a terminal on macOS/Linux, check the tools. Each command should print a version. A missing command means installation or PATH still needs attention.

git --version
gh --version
node --version
npm --version

2 · Create a folder and open it in Codex

  1. Create an independent folder such as Documents/signal-garden in your file manager. Avoid putting a new game inside this book’s repository.
  2. Follow the official desktop quickstart and Windows download guide. Current docs call the application the ChatGPT desktop app; select Codex for software development. Existing Codex app installations can use their project/folder controls.
  3. Sign in with your ChatGPT account, open the game folder as a project, and start a local coding task there. Verify the absolute working path before editing. Choose GPT-6 Astra if offered in your model picker; account access and model options can vary.

The selected local environment must have the tools from step 1. A WSL or remote session has its own environment and may need separate tools and authentication. Keep the app’s permission boundaries; use specific permissions when a necessary action requires them. {{cite:56}}

3 · Optional: use Claude Code in the desktop app

Follow Claude’s desktop quickstart, sign in, select Code → Local → Select folder, and choose the game folder. The Code tab requires eligible subscription access; a free chat account is not sufficient for this route.

Git is needed for worktree isolation and this book’s version-control workflow. Older Windows app versions also required it before any local session.

Desktop includes Claude Code; a separate CLI install is only needed to run claude from a terminal. {{cite:57}}

Use one agent at a time on the same checkout. To compare agents, use separate branches/worktrees with the same baseline and evaluation task.

Prompts can share project documents, but model selection and instruction-file discovery belong to each application; do not assume that every agent automatically reads every other agent’s configuration. See tool and skill selection.

4 · Create GitHub access with HTTPS

  1. Create a GitHub account, verify its email and set up account protection. Skip this if you already have an account. {{cite:60}}
  2. In your local terminal, run the login command below. Complete the browser login yourself. If asked to authenticate Git using GitHub credentials, choose Yes. {{cite:61}}
gh auth login --hostname github.com --git-protocol https --web
gh auth status

Run the status check inside the agent’s environment too. Codex sign-in is separate from GitHub login.

GitHub CLI authentication can also configure Git’s HTTPS credentials, so SSH is optional. Keep passwords, tokens and private keys out of chat and commits.

GitHub CLI normally uses the OS credential store; its documented fallback is a plain-text file if no working credential store is available. {{cite:61}}

5 · Optional: choose SSH instead

If you prefer SSH, follow GitHub’s platform-specific key and ssh-agent guide. Check for existing keys first; never overwrite one accidentally.

A new key can be generated with the command below after replacing the email label. Add a passphrase and follow the guide for your OS. {{cite:62}}

ssh-keygen -t ed25519 -C "your_email@example.com"
# After adding the public key to GitHub:
ssh -T git@github.com

Add only the .pub key under GitHub Settings → SSH and GPG keys. Before accepting a new host, compare its fingerprint with GitHub’s linked official fingerprints.

The test should identify your username; success can still return exit code 1 because GitHub offers no interactive shell. Use an SSH remote such as git@github.com:YOUR_ACCOUNT/signal-garden.git.

GitHub CLI still needs its own login for API operations such as creating a repository. {{cite:62}} {{cite:61}}

6 · Check the project and set commit identity

Paste this read-only prompt in the selected project chat. It checks readiness before the cookbook starts creating files.

{{prompt:setup-preflight.md}}

After Git has been initialized for this project in cookbook step 4, set a missing author name/email locally with the following commands, replacing both values, then continue the commit step. Your GitHub email settings show a no-reply address if you prefer email privacy.

user.name and user.email label commits; they do not log you into GitHub. {{cite:58}}

git config --local user.name "Your Name"
git config --local user.email "YOUR_VERIFIED_OR_GITHUB_NOREPLY_EMAIL"

Saving a file, committing, pushing, and deploying are four different results. To understand existing code, ask the agent to trace input → state → rendering with file references and Git history; see the repair recipe. A commit cannot prove the game works.

7 · Publish with GitHub Pages

Complete and test the game locally first. For this beginner GitHub Free route, use a public repository and publish only content intended to be public. GitHub Pages serves static files; it does not run your Vite dev server or a multiplayer backend. {{cite:46}}

  1. Use the Pages release prompt with your exact account and repository.
  2. For a project URL https://YOUR_ACCOUNT.github.io/signal-garden/, set Vite base to /signal-garden/. Build and preview the output locally.
  3. In the GitHub repository, select Settings → Pages → Source: GitHub Actions. The agent prepares the build/deploy workflow, commits and pushes the intended files. See the full Pages walkthrough.
  4. Wait for the workflow for the expected commit, then verify the public URL, assets, win, loss and restart. A successful push alone is not a deployed game.

Vite’s deployment guide documents the base path, build output and Actions route. dist is its default output; verify your project’s actual configuration. {{cite:12}} {{cite:13}}

8 · Or publish with Vercel Hobby

Vercel Hobby is a free plan for personal, non-commercial use, subject to usage limits. It is not a blanket free tier for a business or commercial game. Check the current plan conditions before choosing it. {{cite:64}}

  1. Use the Vercel release prompt after filling both GitHub and Vercel destinations.
  2. For a static Vite game served at the domain root, use base: '/', the project’s build command (normally npm run build), and its output directory (normally dist). If using both hosts, configure each deployment’s base explicitly.
  3. In Vercel’s New Project flow, connect GitHub, grant access to the selected repository and import it. Review the account/scope, root directory, Vite preset and build settings, then deploy. This integration needs its own repository access; SSH setup does not grant it.
  4. Alternatively, install Vercel CLI with npm install -g vercel and run vercel login. In the game folder, review the project/scope prompts; use vercel --prod when ready to publish production. No extra skill or MCP server is required for the dashboard route.
  5. Check the assigned vercel.app production URL while logged out, the deployed revision, assets and gameplay. Connected Git pushes can trigger later deployments; distinguish preview URLs from production.

The official getting-started guide covers both CLI and dashboard routes. Vercel’s Git and Vite guides explain integration and framework behavior. A private source repository still cannot hide secrets embedded in browser JavaScript. {{cite:63}} {{cite:12}}
