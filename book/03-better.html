The better loop

A better result begins with a smaller uncertainty.

You ask an AI agent to make a beautiful 3D game. It creates a landscape, a character, a menu, and several hundred lines of code.

The screenshot looks promising. Then you press a key: the camera points into a wall, the player slides through a collectible, and nothing explains how to win.

The request was easy to begin and difficult to finish because “good” never became something you could observe.

This book uses one original example, Signal Garden: guide a small maintenance robot around an abandoned rooftop garden, collect three energy cells, avoid a patrolling drone, and power a beacon before time runs out. The game is deliberately small.

It gives us enough movement, collision, feedback, atmosphere, and state transitions to practice making a complete experience.

Give every iteration a question

“Can a new player find the beacon?” is a useful question.

It suggests a route, a camera angle, a first playtest, and a way to judge the change. “Make the game more professional” leaves the agent to guess among textures, controls, menus, sound, or architecture.

The next step is often easier to choose when the current problem is named precisely.

For this book, better means increasing the quality of the player’s experience while keeping the cost of the next change manageable. The first half needs playtesting.

The second needs understandable files, repeatable checks, and recoverable commits. A beautiful frame and a successful build each answer only part of the question.

A model, an agent, and a workflow

  • GPT-6 Astra is the requested model.
  • An agent is the surrounding software that gives that model access to files, a terminal, documentation, and possibly a browser or game editor.
  • A workflow is your agreement about what to build, what evidence to collect, and when to continue.

A pasted prompt cannot give an ordinary chat tools it does not have.

OpenAI’s Astra guidance recommends making autonomy, instruction-file behavior, delegation, and test scope explicit. Use the model name shown by your agent host, and check that the tools needed for the task are available.

The working principle

Write the smallest instruction that carries the intent, constraints, and evidence needed for the next useful decision.

How to use this book

  1. Read the approach comparison before choosing an engine.
  2. Set up the repository and fill the game brief.
  3. Use a compact execution prompt when the brief is clear; use the optional meta-prompt to resolve missing design decisions.
  4. Review available skills before adding project-specific instructions.
  5. Build through useful checkpoints, keep the evidence, and revise the workflow when the model or the task changes.

Try this before you prompt

Write one sentence for the player’s objective, one action that should feel satisfying, and one observable condition that means the first version is done. If those sentences are unclear, work on the game idea first.
