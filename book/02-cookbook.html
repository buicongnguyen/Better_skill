Copy-and-paste cookbook

One worked prompt for every step in the Quick summary.

Start with environment setup. These original examples follow Signal Garden’s game rules.

Paste one prompt at a time into the chat attached to your game folder, inspect the result, then continue. Keep your own agreed requirements when adapting the example.

The recipes are proposed workflows, not a benchmark or a promise that one prompt produces a finished game.

A chatbot without repository and execution tools can help draft a brief or prompt; it cannot inspect your local code, run checks or publish it. For those steps use a coding agent with the selected folder and relevant tools.

In Claude Code, use an available Claude model; writing “Astra” in a prompt does not change the model. Existing project files are the continuing source of truth. {{cite:56}} {{cite:57}}

Edit the short block, keep the detailed instructions

  1. Copy the whole prompt into an unsent chat draft. Then edit the opening block; keep headings and line breaks.
  2. Edit the opening parameters. Choose one agent and, where offered, one engine or video tool. Leave other defaults unchanged when they suit the project.
  3. Match the real environment. Select the model in the app and open the intended folder. Typing a model or tool name does not activate it.
  4. Keep one source of rules. Put design changes in RULE_CHANGES when drafting the brief; later recipes use the agreed project documents. A changed engine choice needs reconciliation with existing work.
  5. Check the result before continuing. Compare it with the completion check. In a release prompt, PUBLISH: YES authorizes the named public release; use NO for local preparation.

What the RTS planning example teaches

The supplied RTS plan separates scope, grouped tasks, tuning values and completion checks. This book adopts that structure: parameters → goal → tasks and constraints → completion check.

A full game specification belongs in the project documents. A follow-up prompt should request the next useful outcome and reference those documents. Keep essential game rules explicit while letting the agent choose routine implementation details; more sections alone do not prove a better game. {{cite:17}}
