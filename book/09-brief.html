Design a game worth finishing

A small world can still have a clear identity.

Signal Garden is an original teaching design. You are a maintenance robot on a forgotten rooftop at dusk.

Three dormant cells can bring a garden’s beacon back to life. A patrolling drone and a short countdown make the route a decision.

The desired feeling is calm exploration interrupted by readable moments of pressure.

The following values are initial design targets. They have not been measured in a completed game. They exist to make the brief concrete enough to build and then revise.

Define the core loop in verbs

Observe → choose a route → move → collect → evade → return → activate. Each verb should have a visible consequence. A cell disappears once, the counter increases once, and the beacon’s appearance changes when it is ready.

A hit has clear feedback and a short recovery period. Losing gives an immediate route back into play.

Decide the edge cases before they become bugs

  • For the first implementation, check loss conditions before allowing beacon activation in each simulation step.
  • If the timer reaches zero in that step, the result is a loss.
  • E should act on a fresh key press, and activation requires the player to be within two units of the beacon.
  • After a terminal result, movement, collection, damage, and the timer stop until restart.
  • Restart is available from paused, won, and lost.
  • It resets the player, cells, health, timer, drone progress, cooldowns, effects, and held input, then starts a fresh playing round.
  • Losing window focus clears input and pauses an active round; returning focus requires an explicit Resume action.

These are our chosen rules, shared by the prompts and acceptance checks.

Pick a single convention for coordinates and units. In the proposed Three.js game, use Y as up and move on the X/Z plane.

Keep character speed in units per second. Decide these once in the brief so movement, camera, collision, and tests do not silently use different assumptions.

Give visual references a job

Collect or create references you have permission to use. Describe what each reference contributes: palette, camera height, silhouette, lighting, or UI density. Treat a reference as a design constraint, not an instruction to copy another game’s characters, brand, or proprietary assets.

For Signal Garden, ask for a greybox image first, then a visual pass that keeps the same camera and geometry. Comparing like-for-like views makes the effect of lighting and material changes easier to judge. A more elaborate scene is not automatically a better scene.

Write the exclusions

For the first release, exclude multiplayer, procedural worlds, inventory systems, dialogue trees, and multiple levels. Add one only when it strengthens a playtested core loop enough to justify the extra work.

Check the mathematics behind the rules

For keyboard input (x,z), each component is -1, 0, or 1. Its length is sqrt(x*x + z*z).

A diagonal (1,1) has length sqrt(2), so unnormalized diagonal motion is about 41% faster. Divide a nonzero vector by its length, then multiply by speed in metres/second and simulation time in seconds.

Zero input must stay zero. This is an elementary derivation, not a benchmark.

n = Math.hypot(x, z)
dx = n === 0 ? 0 : (x / n) * speed * dtSeconds
dz = n === 0 ? 0 : (z / n) * speed * dtSeconds
// At 4 m/s and 0.25 s: total displacement = 1 m.
// Diagonal components are each about 0.7071 m.

This formula is for digital keyboard input. A future analog stick should preserve partial deflection, typically clamping length to at most 1 after a dead zone instead of normalizing every nonzero input.

Collision resolution is a separate step: a large displacement can cross a thin obstacle. Use suitable bounded simulation steps or swept collision checks and test the relevant speeds; elapsed-time scaling alone does not prevent tunneling.

  1. For this design, “within two units” means ground-plane centre-to-centre distance ≤ 2; the equivalent squared-distance check is dx*dx + dz*dz <= 4.
  2. Use simulation time for damage cooldown and the round timer so pause freezes both.
  3. Process damage and elapsed time, settle loss, and only then allow activation if still playing.
  4. A single phase value plus centralized transition checks prevents contradictory terminal screens.

These are explicit implementation rules for our original design.
